## Architecture

**Takt** is a macOS menu bar task scheduler. Two-layer architecture:

- **`libtakt/`** — Rust core library (static `.a`). Exposes API to Swift via UniFFI. All business logic, persistence (SQLite/sqlx), scheduling (tokio-cron-scheduler), and action execution live here. A global tokio runtime (`tokio_runtime()` in `lib.rs`) is required because UniFFI polls async futures from non-tokio threads.

- **`macos/Takt/`** — SwiftUI frontend (macOS 14+). Implements `PlatformBridge` trait (`platform.rs`) for native capabilities: notifications, main-thread dispatch, user activity detection, and EventKit calendar access.

### Key constraints

- **UniFFI boundary**: types crossing Rust↔Swift use `#[derive(uniffi::Record)]` / `#[derive(uniffi::Enum)]`. `PlatformBridge` uses `#[uniffi::export(with_foreign)]`.
- **Main-thread dispatch**: Rust calls macOS APIs via `platform::run_on_main()` through the bridge callback registry. Swift MUST use `DispatchQueue.main.async` (not `.sync`) to avoid deadlock.
- **Generated bindings**: `macos/Takt/Generated/` is auto-generated by `scripts/build-rust.sh` — never edit manually.
- **Build pipeline**: Xcode build phase calls `scripts/build-rust.sh`. Requires `rustup target add aarch64-apple-darwin`.

## Pitfalls (learned the hard way)

- **No `Option<Option<T>>` in UniFFI types.** Compiles in Rust but generates broken Swift bindings. Use sentinel values or an enum wrapper to distinguish "not sent" from "set to null". (`UpdateTaskParams.description` still has this — needs fixing.)

- **ALL EventKit calls must run on main thread** — not just permission requests, but also `authorizationStatus` and calendar/event queries. Without this, silent deadlock on startup when Calendar-scheduled tasks exist in DB.

- **Calendar entitlement required even without sandbox.** macOS TCC requires `com.apple.security.personal-information.calendars` in entitlements for the permission dialog to appear. Without it, `requestFullAccessToEvents` silently returns `.denied`.

- **Request calendar permission directly from SwiftUI, not via Rust round-trip.** The UniFFI→Rust→tokio→FFI→Swift→main chain doesn't reliably show the system permission dialog when launched via LaunchServices. Call `EKEventStore.requestFullAccessToEvents` directly from the view.

- **Use `ObservableObject`+`@Published` for AppDelegate, not `@Observable`.** `@Observable` with `@NSApplicationDelegateAdaptor` doesn't reliably trigger `MenuBarExtra` re-renders when launched via LaunchServices. Two attempts were reverted.

- **Xcode build phase: use stamp-file, not inputPaths for Rust.** Xcode `inputPaths` doesn't track files recursively, so `.rs` changes go undetected. Use `alwaysOutOfDate=1` + `.bindgen-stamp` mtime comparison — cargo build is a fast no-op (~0.5s) when nothing changed.
